# M1 Alpha：实现说明

对应 [technical-design.md §23](technical-design.md#23-路线图) 的 M1。按约定顺序完成：自动化 → HA 导入与备份 → 插件宿主与 SDK → ESPHome / Zigbee → HAP 分片与单文件发行。

## 已交付

| 项 | 实现 | 位置 |
| --- | --- | --- |
| 自动化引擎 v1 | HA 结构（triggers / conditions / actions），接受旧写法 `platform:` / `service:`；7 种触发器、7 种条件、10 种动作；single/restart/queued/parallel；运行追踪；版本历史；内置 NOAA 日出日落 | `packages/automation` |
| HA 风格实体状态与服务 | `light.turn_on` 等服务 → 能力命令；实体状态（`on`/`off`/数值 + 属性）供自动化、导入与后续 HA API 兼容层复用 | `packages/core/src/entity-state.ts`、`services.ts` |
| Webhook | `/api/webhook/<id>`，无需认证（ID 即密钥），默认仅局域网 | `apps/server/src/routes/automations.ts` |
| 自动化界面 | 列表（自然语言摘要）、YAML 编辑器（实时校验、实体选择）、运行追踪时间线、版本与恢复 | `apps/web/src/pages/automation*.tsx` |
| Agent | MCP `list_automations`、`get_automation`（含追踪）、`propose_automation`（只存为禁用草稿，不可覆盖） | `packages/agent` |
| HA 导入器 v1 | 配置目录或未加密备份；`!include*` / `!secret`；区域→房间（HA 区域 ID 作为别名）、MQTT 设备按标识匹配、**沿用 HA 实体 ID**、自动化（默认禁用；不合法的以禁用状态保留并附错误）；dry-run 报告；可撤销 | `packages/importer-homeassistant` |
| 备份 / 恢复 | `VACUUM INTO` 快照 + secrets + 配置 + 插件数据；可选 scrypt + AES-256-GCM 加密；离线恢复并保留原目录；每日自动备份保留 7 份 | `packages/core/src/backup.ts`、`tar.ts` |
| 插件 SDK | `defineAdapter` + `PluginContext` | `packages/sdk`，指南 [plugins.md](plugins.md) |
| 插件宿主 | 每插件独立进程（IPC）；监督器退避重启、离线标记、反复崩溃后停用；官方插件可 in-process | `packages/plugin-host` |
| 虚拟开关插件 | 持久化开关与瞬时按钮（Siri 场景触发） | `plugins/virtual` |
| ESPHome | Native API（含 Noise 加密）、mDNS 发现；灯（亮度/色温/RGB）、开关、传感器、二元传感器 | `plugins/esphome` |
| Zigbee | zigbee-herdsman + Z2M 设备库；曝光→端点映射、fromZigbee/toZigbee 转换；配对模式开关；**接管 Zigbee2MQTT 网络免重新配对** | `plugins/zigbee` |
| HAP 分片 | 超过 149 个配件自动新增桥；配件→桥的分配持久化且永不改变 | `packages/exporter-homekit` |
| 多路设备拆分 | 每个通道一个配件；首通道与传感器保留原配件 UUID | 同上 |
| 单文件可执行程序 | esbuild 打包 + Node SEA：Web 界面作为内嵌资源；插件子进程由同一二进制以 `LIVYNQ_ROLE=plugin-host` 重新启动；内置虚拟开关插件 | `scripts/build-sea.ts`、`apps/server/src/sea-entry.ts` |
| 安装与发行 | 安装脚本（systemd / launchd、服务用户、串口权限）；CI（Linux x64/arm64、macOS）；打 tag 自动构建并发布二进制 | `installers/install.sh`、`.github/workflows` |

## 验证情况

- 51 个自动化测试全部通过（`pnpm test`），类型检查通过。
- 单文件程序在本机（macOS arm64）从空目录启动验证：Web、MQTT 内置 Broker、HomeKit、虚拟开关、进程隔离插件、CLI、MCP stdio。
- **未在真实硬件上验证**：Zigbee 协调器、ESPHome 设备、iPhone 配对。Zigbee 使用真实 Z2M 设备库 + 模拟控制器测试；ESPHome 使用模拟节点测试并对真实库做了加载冒烟。
- 安装脚本与 GitHub Actions 只做了语法检查，需在首次发版时验证。

## 与设计文档的偏差

| 设计 | 实际 | 说明 |
| --- | --- | --- |
| 单文件程序 60–80MB | 约 117MB（Node 运行时约 110MB） | 设计文档已更正；发布时提供 gzip（约 40MB） |
| Jinja 模板兼容子集 | 自动化暂不支持模板 | 导入时含模板的自动化以禁用 + 错误说明保留；M2 实现 |
| ESPHome / Zigbee 进入单文件程序 | 不打包，作为磁盘插件加载 | 含原生模块（serialport）与 WASM，需随平台安装；npm 发布插件后通过 `livynq plugin add` 安装 |
| 自动化 `delay` 重启后恢复 | 未实现 | 重启会中止运行中的自动化（追踪记为 aborted） |

## 已知限制

- 插件以 npm 包分发需要先把 `@livynq/sdk` 与官方插件发布到 npm。
- HomeKit 配件仍按 Livynq 设备名初始命名；Apple Home 中修改的名称不回写。
- 导入器只接管 MQTT 设备；ZHA / Z-Wave JS / Matter 设备在报告中列出并给出迁移建议。
