## 与设计文档的偏差（有意为之）

| 设计文档 | M0 实际 | 原因 / 后续 |
| --- | --- | --- |
| TypeBox Schema → OpenAPI | 能力参数用自带的 JSON-Schema 兼容小型 Schema（`packages/model/src/schema.ts`），HTTP 路由手写校验 | 少一个依赖；OpenAPI 生成放到 M1，届时再评估 TypeBox |
| `hap_id_map` 表自管 AID/IID | 使用 HAP-NodeJS 的 IdentifierCache（存于 `secrets/hap/`）并关闭 `shouldPurgeUnusedIDs`，UUID 由设备 ID 确定性生成 | 同样满足"永不复用、永不重排"，且有测试保护；需要"替换设备"功能时再引入映射表 |
| M0 仅只读 MCP | 增加了 `control_device`，但只对 `control` 作用域令牌开放，且设备可设为 Agent 只读/隐藏 | 当前所有能力均为低风险；风险分级 + 人工确认按计划在 M2 |
| Turborepo / tsup / Vitest / Drizzle | 不使用 | 服务端零构建，测试用 `node:test`，SQL 直接写；符合依赖预算 |
| 每设备多配件（多路开关） | 一个设备一个 HAP 配件，各端点为子服务 | 多路开关拆分配件放到 M1 |
| 单桥 149 配件后自动分片 | 超出时记录告警并跳过 | M1 |

## 已知问题

- ciao（HAP-NodeJS 的 mDNS 实现）在首次广播完成前就停止时会遗留一个 UDP 套接字；只会在测试中快速重启时出现，测试脚本使用 `--test-force-exit`。
- `node:sqlite` 在 Node 24 仍标记为实验特性；启动脚本使用 `--disable-warning=ExperimentalWarning`。
- Dockerfile 尚未在本机验证（开发环境无 Docker）。
- 未经真实 iPhone 配对验证；HAP 层已通过本机发布与 ID 稳定性测试。
